ข้อมูลจริงจาก log/trace/การตรวจแบบปิดป้าย — ต.ค. 2026 · โค้ดอยู่ที่ `tools/novel-reader/`

## 1. ตัวเลขหลัก

| | ค่า |
|---|---|
| ค่าแปลต่อตอน (GPT-5.6 Luna, ระบบเต็ม) | ~$0.0067–0.008 (≈ ฿0.25) |

| Codex (agent) แปลเอง | ~100 วิ/ตอน, ย่อหน้ารวมกัน 144/145 ตอน, ไม่อัปเดตคลัง — ไม่คุ้ม |
| จุดผิดต่อตอนหลังระบบเต็ม | ~4–6 (ส่วนใหญ่ความหมายคำ/เชิงอรรถ) |

เงินส่วนใหญ่ไปที่ **token ขาออก (ข้อความไทยที่โมเดลพิมพ์)** — ไทยกิน token มาก ตอนจีน 2,500 ตัว ≈ ไทย 3,500–4,500 token
→ ลดเงินได้จริงมีแค่ 2 ทาง: ลดจำนวนรอบที่โมเดลต้องพิมพ์ข้อความยาว หรือใช้รุ่นที่ token ขาออกถูก

## 2. สัดส่วนค่าใช้จ่ายต่อขั้น (trace 140 ตอน, ตอน 451+)

| ขั้น | $/ตอน | หมายเหตุ |
|---|---|---|
| แปลร่าง | 0.0035 (43%) | ขาออก ~5,200 token |
| เกลา | 0.0031 (38%) | แก้จริงแค่ **19% ของย่อหน้า** (ส่วนต่างความยาวกลาง 5%) |
| ตรวจสำนวน/ความหมาย | 0.0012 (15%) | แก้ความหมาย ~7 จุด/ตอน, เพิ่มศัพท์ ~2, เชิงอรรถ ~2 |
| อื่นๆ | <0.0003 | แก้สรรพนาม, แก้บรรทัดจีนหลุด |

ส่วนประกอบ prompt ขั้นร่าง (ตัวอักษรต่อคำขอ): คลังคำ JSON 3,100 · กฎสรรพนาม 1,500 · **ต้นฉบับแค่ 1,500**
→ prompt ส่วนเกินใหญ่กว่าเนื้อที่แปล ; คลังส่งข้อมูลซ้ำกับกฎสรรพนาม (pronouns/self/called) → ตัดแล้วถูกลง ~10% ไม่เสียคุณภาพ

## 3. การทดลองที่ได้ผล / ไม่ได้ผล

**ได้ผล**
- **บังคับคำแทนตัว/คำลงท้ายด้วยโค้ด** (ไม่ใช่แค่สั่งใน prompt): โมเดลลอยตามฉากเสมอ ; ใส่รายการบังคับแยกหัว prompt + โค้ดแก้หลังแปล (เฉพาะในเครื่องหมายคำพูด, ให้ LLM แค่ระบุผู้พูด)
- **เลขย่อหน้า ⟦n⟧** ทั้งขาเข้า/ขาออก: ย่อหน้าหาย/รวม 7 → 0 ; ทำให้ทุกขั้นหลังเทียบต้นฉบับทีละย่อหน้าได้
- **ดึงต้นฉบับทั้งเรื่องก่อน → เก็บคำศัพท์ล่วงหน้า (ทีละ 10 ตอน, ส่งแค่คำจีนที่มีแล้ว) → แปลหลายตอนพร้อมกันในโปรเซสเดียว** (คลังในหน่วยความจำชุดเดียว ชื่อไม่ชน) — เก็บคำ 400 ตอนใช้แค่ $0.11
- แปลงเลขจีนผสม (18070亿4642万5216) ด้วยโปรแกรมก่อนส่ง
- เกลาแบบ "ส่งเฉพาะย่อหน้าที่แก้" + ตัวกันรายย่อหน้า (เชิงอรรถหาย / ยาวผิดปกติ / บอกเล่ากลายเป็นคำถาม)
- บันทึก prompt+คำตอบทุกครั้ง (`trace/`) — ทำให้วิเคราะห์ส่วนนี้ได้

**ไม่ได้ผล / ผลกลับ**
- **ตัดตอนเป็น 2 ชิ้นแปลขนาน**: เร็วขึ้นแต่ชิ้นหลังเสียบริบท → คำบรรยายหลุดเป็น "ฉัน" 0.5–0.7 บรรทัด/ตอน (ตรวจแล้วปกติ 0.04) ; ตรวจปิดป้าย 46 จุดผิด vs ชิ้นเดียว 33 → **ความเร็วให้ได้จากการแปลหลายตอนพร้อมกันแทน**
- **ให้โมเดลปรับคลังให้สม่ำเสมอทั้งชุด**: แก้ได้บางคำแต่ทำคำเสีย ("ควบคุมธาตุไฟธาตุ", "กองทัพ…กองทัพ") → ใช้แค่ตรวจชื่อไทยชนกันด้วยโปรแกรม
- **คลังความหมายคำ (senses)**: ใน 4 ตอนทดสอบ โมเดลแปลคำเหล่านั้นถูกอยู่แล้ว ; ใส่ 2 ความหมายในรายการเดียวทำให้เลือกผิด → ใส่คำแปลเดียว ; เก็บไว้เพราะแทบไม่เสีย token
- **คลังประโยคที่แปลแล้ว (translation memory)**: ย่อหน้าซ้ำเป๊ะ 9.8% แต่เป็นตัวอักษรแค่ 2.2% (บรรทัดสั้น) — ไม่คุ้มทำ
- **เชิงอรรถ**: ผู้ตรวจลบ ~2/ตอน ≈ เกือบทั้งหมดที่ใส่ → จำกัด 1/ตอน
- ขอแปลใหม่เมื่อย่อหน้าไม่ครบ: โมเดลรวมย่อหน้าเดิมซ้ำทุกครั้ง เสียเวลาเปล่า

## 4. ตัดขั้นเกลาได้ไหม (ปิดป้าย 6 ตอน)
ไม่เกลา: จุดผิด 35 vs เกลา 33 แต่ภาษาแข็งกว่า (ประโยคแข็ง 9 vs 5) ; ค่าใช้จ่ายครึ่งเดียว
→ งบจำกัดมาก: ตัดเกลาได้โดยความหมายไม่เสีย ; ต้องการภาษาลื่น: คงไว้

## 5. วิธีวัดผลที่เชื่อได้
- ผู้ตรวจ (agent) คนละคนนับต่างกันได้ 2 เท่า (36 vs 19 ในชุดเดียวกัน) → **ให้คนเดียวเทียบทุกแบบในตอนเดียวกันแบบสลับป้าย**
- เกณฑ์นับเดียวกันทุกครั้ง: สรรพนาม / ความหมาย / ศัพท์ / ภาษาเพี้ยน / เชิงอรรถ / ย่อหน้า / สำนวนแข็ง
- ตรวจด้วยโปรแกรมก่อนเสมอ: จำนวนย่อหน้า, อักษรจีนหลุด, "ฉัน" ในคำบรรยายที่ต้นฉบับไม่มี 我

## 6. ลำดับงานที่แนะนำสำหรับเรื่องใหม่
1. ดึงต้นฉบับทั้งเรื่อง (`prefetch.ts`, เว้นจังหวะ ~1.2 วิ)
2. เก็บคำศัพท์ล่วงหน้า (`extract-terms.ts --range`) → ตรวจชื่อชน → `--apply`
3. ตั้ง self/คำลงท้ายของตัวหลักใน glossary ก่อนแปล (ตัวรองเติมระหว่างแปล)
4. แปล 5–10 ตอนแรก → ตรวจละเอียด → แก้ prompt/คลัง
5. แปลทั้งเรื่องแบบหลายตอนพร้อมกัน (`translate.ts --raw --workers 8`) ด้วยรุ่นราคาถูก
6. ตรวจสุ่ม + ตรวจด้วยโปรแกรม → แก้เป็นชุด ; คำที่ผิดซ้ำเข้า `senses.json`
