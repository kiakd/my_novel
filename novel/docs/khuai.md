สวัสดีครับ จากที่ลองเล่น และลองสร้างบอทมาได้สักพัก พบว่าปัญหาหนึ่งของครีเอเตอร์อย่างเราๆ คือ โควต้า 6000 ตัวอักษร
ผมเลยจะขออนุญาตแชร์เทคนิคส่วนตัวที่ผมใช้ ในการรีดประสิทธิภาพบอท ภายใต้ข้อจำกัดนะครับ
ปล. หากใครรู้อยู่แล้ว ต้องขออภัยด้วยนะครับ
สำหรับการสร้าง ChatBot ใน KhuiAI ให้มีประสิทธิภาพ แม้ว่าใน KhuiAI จะเอื้อต่อการเขียน prompt แบบการพรรณา (prose prompt) แต่การใช้รูปแบบของ syntax coding จะช่วยให้โมเดลของ LLM (Large Language Model) ที่รันบอท เข้าใจตรรกะ และโครงสร้างได้ชัดเจนกว่าการเขียน prose prompt
โดยในส่วนของเรา เราใช้รูปแบบของ xml+json format เนื่องจากง่ายต่อการทำความเข้าใจ ไม่จำเป็นต้องใช้ความรู้การเขียนโปรแกรมขั้นสูง ก็สามารถเขียนเองได้ โดยมีรูปแบบโครงสร้าง ดังนี้
<char>
<appr> ลักษณะทางกายภาพ เช่น รูปร่าง หน้าตา สีผม อายุ etc. </apr>
<prf> ประวัติ เช่น การศึกษา ความสามารถ </prf>
<mnd> วิธีคิดและมุมมอง (mindset) </mnd>
<behav> ลักษณะนิสัย </behav>
<relate> ความสัมพันธ์กับ user และตัวละครอื่น (ถ้ามี) </relate>
<ooc> คำสั่ง ooc ต่างๆ เพื่อกำกับโลจิกตัวละคร
[ooc...]
</ooc>
</char>
ซึ่งสามารถอธิบายได้ ดังนี้
1. <char> คือการกำหนดกรอบของตัวละคร(Character) ทั้งหมด อะไรที่อยู่ระหว่าง <char>...</char> จะเป็นส่วนที่โมเดลนำไปประมวลผล โดยมากมักกำหนด ชื่อ นามสกุล ฉายา ตามตัวอย่าง
<char name="" surname="" nickname="" alias="">
ข้อสังเกต: ผมใช้วิธีแยกชื่อกับนามสกุล เนื่องจากตัวละครบางตัวอาจมีชื่อกลาง การแยกแบบนี้ จะทำให้โมเดลประมวลผลง่ายขึ้น
2. <apr> คือการกำหนดลักษณะทางกายภาพของตัวละคร (Appearance) เช่น เขื้อชาติ สัญชาติ สีตา สีผม เครื่องแต่งกาย แนะนำให้ใช้คำสำคัญสั้นๆ แทนการบรรยาย คั่นด้วยเครื่องหมายจุลภาค (,) เช่น
<apr>หญิง ชาวเชค, อายุ 18, สมส่วน, ผมยาว สีบลอนด์ มัดหางม้า, ดวงตาสีฟ้า, ใบหน้าตกกระ, สวมแว่น, ใส่ชุดนักเรียน</apr>
เพื่อประหยัดข้อความ และให้โมเดลเข้าใจง่าย
ข้อสังเกต: ควรเรียงลำดับจากภาพกว้าง เช่น เพศ เชื้อชาติ อายุ ไล่ไปหารายละเอียดปลีกย่อย เช่น เครื่องแต่งกาย รอยสัก accessories ต่างๆ
ข้อควรระวัง: หลีกเลี่ยงคำขยายที่ฟุ่มเฟือย เช่น 'มีดวงตาที่กลมโตสีฟ้าใสราวกับน้ำทะเล' ให้ใช้เพียง 'ดวงตาสีฟ้า, กลมโต' ก็เพียงพอแล้ว เพื่อให้โมเดลไม่เสียสมาธิกับคำสร้อย เนื่องจาก AI โดยเฉพาะ LLM จะประมวลผลจากคำสำคัญเท่านั้น
3. <prf> คือการกำหนดประวัติของตัวละคร (Profile) เพื่อให้ AI สะดวกต่อการอ้างอิง และนำไปใช้
ส่วนนี้ ผมมักแยกย่อยลงไป เป็น sub tag เช่น
<prf>
<bio> ลูกคนเดียว,ครอบครัวนักการเมือง,พ่อเสียชีวิต,แม่ป่วยติดเตียง</bio>
<skill> ป. โท บริหารธุรกิจ+it, ป. ตรี รัฐประศาสนศาสตร์, จบ RANEPA, เชี่ยวชาญด้าน it+การเจรจา</skill>
</prf>
3. <mnd> เป็นส่วนที่กำหนด วิธีคิด และ มุมมอง (Mindset) ที่ตัวละครมี โดยโมเดล LLM จะใช้ข้อมูลในส่วนนี้ เป็นกรอบ framework ร่วมกับนิสัยในหัวข้อถัดไป เพื่อกำหนดเป็นการกระทำโต้ตอบกับเรา
โดยในส่วนนี้ แนะนำให้ใช้คำสำคัญสั้นๆ ไม่เกิน 2-3 คำ เพื่อป้องกันนิสัยตีกันเอง จนตัวละครหลุด เช่น
<mnd> ความแข็งแกร่งคือความถูกต้อง, ผู้ชนะคือผู้นิยามทุกสิ่ง </mnd>
ข้อสังเกต: กากำหนดกรอบแนวคิด มีผลต่อการกำหนดนิสัยในหัวข้อถัดไป ตลอดจนการแสดงออกของบอท ดังนั้น ข้อมูล 2 ส่วนนี้ ไม่ควรขัดแย้ง หรือแตกต่างกันเกินไปจนไม่สุดสักทาง
4. <behav> ส่วนนี้คือการกำหนดลักษณะนิสัย (Behavior) ของบอท เพื่อให้ AI นำไปประมวลผล โดยวิธีที่ได้ผลที่สุด และไม่ทำให้ตัวละครหลุด หรือที่เรียกว่า หลุดคาร์ คือการกำหนดคำสำคัญ คั่นด้วยจุลภาค 3-5 คำ เช่น
<behav> เด็ดขาด,จริงจัง,เงียบขรึม,เจ้าเล่ห์ </behav>
ทั้งนี้ เพื่อให้ง่ายต่อ AI ในการนำไปคำนวณและท่าทางการแสดงออกของตัวละคร
จากกรณีตัวอย่าง สมมุติว่าถ้า
<mnd> คือ ผู้ชนะคือผู้นิยามทุกสิ่ง และ <behav> คือ เจ้าเล่ห์
บอทจะไม่ได้แค่โกงครับ แต่มันจะโกงแบบ 'มีเหตุผลที่เหนือกว่า' มาอ้างเสมอ
5. <relate> คือการกำหนดความสัมพันธ์ (Relation) ระหว่างบอทกับผู้เล่น และตัวละครอื่นๆ เพื่อนำไปคำนวณร่วมกับกรอบความคิดและนิสัยในการแสดงออก เช่น
<relate>
{{user}} = "คนแปลกหน้า", พัฒนา=true
</relate>
หมายความว่า ช่วงแรกบอทจะมองเราเป็น 'คนแปลกหน้า' แต่สามารถเพิ่มระดับความสัมพันธ์ได้ เมื่อเวลาผ่านไป
เทคนิค: ในการใช้งานจริง เราสามารถแยกสถานะทางสังคม หรือความสัมพันธ์ออกมา เพื่อเพิ่มระดับความซับซ้อนทางอารมณ์ และการแสดงออก เช่น
{{user}} = "บอส", ความซื่อสัตย์ =1.0, แอบชอบ = true, ปากไม่ตรงกับใจ = true, พัฒนา = true
แบบนี้ จะทำให้ตัวละคร แอบชอบผู้เล่น แต่จะแสดงอาการปากไม่ตรงกับใจ เมื่ออยู่ต่อหน้า
หรือ
{{user}} = "พันธมิตรทางธุรกิจ", ความซื่อสัตย์=0.5, หักหลัง=0.2, ความสัมพันธ์ทางกาย = true, รัก = false, พัฒนา = true, user_relate != "คนรัก"
จะทำให้ความสัมพันธ์เป็นแบบเพื่อนรักหักเหลี่ยมโหด ที่มี something wrong ได้ แต่จะไม่มีวันข้ามขั้นเป็นคนรัก
ซึ่งจะเห็นได้ว่า ในส่วนนี้ เป็นการสร้าง 'มิติที่ขัดแย้ง' ให้ตัวละคร ยิ่งเราวาง Logic ความสัมพันธ์ให้ซับซ้อน บอทก็จะยิ่งดูมี 'หัวใจ' และมี 'ลับลมคมใน' มากกว่าการเซตความสัมพันธ์แบบราบเรียบทั่วไป
ข้อสังเกต: การใช้เครื่องหมาย != (ไม่เท่ากับ) คือการสั่งให้ AI 'เว้นระยะห่าง' จากสถานะเป้าหมาย เป็นเทคนิคการล็อคคาร์ (Character Locking) ที่ได้ผลดีที่สุดในการคุมความสัมพันธ์ไม่ให้ข้ามเส้นที่ผู้เล่นวางไว้
6. <ooc> ในส่วนนี้ เป็นการใส่คำสั่ง ooc (Out of Character) เพื่อเป็น key line ในการกำกับการประมวลผลของบอท เช่น ผลลัพธ์ ตรรกะการกระทำของตัวละคร เป็นต้น
โครงสร้างมักประกอบด้วย Square Brackets เพื่อเป็นการเปิดและปิดคำสั่ง เช่น
[ooc: output_config {
header = "[📍{{loc}}, 🕒 {{time}}]",
auto_context = true,
length >= 1800_chars, (กำหนดความยาว)
narr_style: ["Psychological_Horror", "Sensory_horror"], (กำหนดโทนการเล่าเรื่อง)
dialogue: ["short_and_sharp", "show_dont_tell"], (กำหนดลักษณะการบรรยาย)
no_cutoff = true,
anti_godmoding=true}]
โดยผลลัพธ์นี้ เมื่อบอทตอบ rp เรา คำตอบจะ
- มีสถานที่ และเวลากำกับเสมอ
- กำหนดโทน และสไตล์การตอบ เช่น สยองขวัญ แอ็คชั่น
- บอทจะไม่บรรยายแทนผู้เล่น
ข้อสังเกต: การใช้คำสั่งใน [ooc: ...] เปรียบเสมือนการวาง 'กฎฟิสิกส์' ให้กับโลกจำลองของเรา ยิ่งเรากำหนดเงื่อนไขให้กระชับและเป็นระบบ (Syntax) มากเท่าไหร่ บอทก็จะทำงานได้เสถียรและประหยัด Token มากเท่านั้น
โดยในปัจจุบัน โมเดล LLM ส่วนใหญ่ สามารถเข้าใจภาษาไทย ทำให้สามารถเขียนคำสั่ง ooc ที่ซับซ้อนได้ โดยไม่ต้องมีพื้นฐานการเขียนโปรแกรม เช่น
[ooc: การโต้ตอบ {
ถ้า {{user}} "ด่า {{char}}" == true, {{char}} = "หงุดหงิด"}]
ผลลัพธ์ที่ได้ เมื่อผู้เล่นด่าบอท บอทจะรู้สึดหงุดหงิด
​[ooc: เงื่อนไขการตอบโต้ { ถ้า {{user}} "พยายามจับตัว {{char}}" == true && ความสัมพันธ์ < "สนิทสนม", ผลลัพธ์ = "{{char}} จะสะบัดตัวออกและแสดงท่าทีรังเกียจอย่างชัดเจน" }]
ผลลัพธ์ที่ได้ ช่วยคุมไม่ให้บอท "ใจง่าย" เกินไป ถ้ายังไม่สนิทกันแล้วมาแตะเนื้อต้องตัว บอทจะล็อคท่าทางให้ปฏิเสธทันที
​[ooc: บรรยากาศ { ถ้า สถานที่ == "โรงพยาบาล" || สถานที่ == "ห้องตรวจ", {{char}} = "วิตกกังวล", พฤติกรรม = "อยู่ไม่สุข, พยายามหาทางหนี, ระแวงทุกเสียงที่ดังขึ้น" }]
​คำอธิบาย: ใช้เครื่องหมาย || (หรือ) เพื่อรวมเงื่อนไข ทำให้บอทเปลี่ยนบุคลิกไปตามสถานที่ได้อย่างสมบูรณ์แบบ
จะเห็นได้ว่า โมเดล LLM ในปัจจุบันฉลาดพอที่จะเข้าใจตรรกะภาษาไทย ดังนั้นไม่ต้องกังวลเรื่องไวยากรณ์ภาษาอังกฤษ แต่ให้เน้นที่ 'ความชัดเจนของเงื่อนไข และผลลัพธ์' เป็นหลักครับ
