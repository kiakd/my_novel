### [ร-1] [C] เซ็นเซอร์อุณหภูมิเครื่องยนต์ดิบถูกใช้ "จับระลอกความร้อนของยานเบรย์" — เกินฟังก์ชันทะเบียนหมวด C และเป็นกลไกแบกชัยชนะของแกนตอน (คลาสเดียวกับบั๊ก [ร-1] ep004)

- **ตำแหน่ง**: ep005.md บรรทัด 117 และ 119 (ฉาก 3 — หัวใจ silent running)
- **excerpt ±2 บรรทัด (115–119)**:

> (115) เวลาผ่านไป — เท่าไรเขาไม่รู้ ในความเงียบนั้นวินาทีกลายเป็นนาทีที่นับไม่ถ้วน
> (117) แล้วเขาก็เห็นมัน — เงาที่เคลื่อนผ่านขอบจอครึ่งมืด กับระลอกความร้อนจางๆ ที่เซ็นเซอร์อุณหภูมิจับได้: เบรย์กำลังกวาดพื้นที่
> (119) ภูมิอ่านแพตเทิร์นการเคลื่อนที่ … จากเงาบนจอกับระลอกความร้อนที่เซ็นเซอร์ดิบยังจับได้: เส้นทางกวาดสม่ำเสมอเหมือนลอกจากหน้าหนังสือ …

- **เหตุที่สงสัย**:
  1. ทะเบียนหมวด C นิยามไว้ว่า "เซ็นเซอร์อุณหภูมิเครื่องยนต์ดิบ = เซ็นเซอร์ดิบอ่านตรงจากเครื่องยนต์" — คือวัด *เครื่องของตัวเอง* (บ.103 ใช้ถูกต้อง: "อ่านค่าความร้อนที่ค่อยๆ เย็นลง" ของเครื่องตัวเอง) แต่บ.117/119 ใช้มันตรวจจับความร้อนของ *ยานอีกลำ* ที่ระยะไกลในสุญญากาศ = ฟังก์ชันใหม่ที่ไม่มีในทะเบียน (กฎหมวด C: "เครื่องวัด/ระบบใดไม่อยู่ในลิสต์ = ไม่มีอยู่")
  2. ข้อมูลจากเซ็นเซอร์ตัวนี้คือสิ่งที่พาภูมิไปสู่การล็อกยิงชนะ — จุดแบกชัยชนะของตอน เหมือนเคส [ร-1] ของ ep004 ที่บก.ให้เป็นร้ายแรง
  3. ต้นเหตุน่าจะมาจากแผนเอง: หมายเหตุ Gate ข้อ 3 สั่ง "ให้น้ำหนักการอ่านอยู่ที่ 'เงาบนจอ/เซ็นเซอร์อุณหภูมิ'" — แผนกับทะเบียนขัดกันเอง ดราฟต์เลยตกร่องนี้
- **คำถาม**: ตั้งใจตาม Gate note (ถ้าใช่ — ต้องเพิ่มรายการ "เซ็นเซอร์ความร้อนภายนอก/ชุดเซนเซอร์แพสซีฟของยาน" เข้า items-locations หมวด C หรือแก้นิยามตัวเดิม) หรือคลาดจริง? ทางแก้เบาที่เป็นไปได้: ให้การอ่านทั้งหมดอยู่ที่ "เงาบนจอ" (ชั้นเซนเซอร์ยานที่ยังเปิดครึ่งจอ) แล้วตัดบทบาทเซ็นเซอร์อุณหภูมิออกจากการจับเบรย์ — วินเคาะทางไหน?
