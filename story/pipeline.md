# Pipeline ทีมนิยาย v2.3 — ออกแบบโดยเพม (CEO), อัปเดต 11 มิ.ย. 2026

## v2.5 — ลำดับความสำคัญสูงสุด: ความต่อเนื่อง > ความเร็ว (CEO, 11 มิ.ย. 2026)

**คำสั่งหลัก: ห้ามหลุด character · เนื้อเรื่องห้ามหลุด ต้องไหลลื่นต่อกัน · ปมที่ผูกไว้ห้ามหาย · ลำดับฉากต้องถูก — ยอมช้าลงได้เสมอเพื่อสิ่งเหล่านี้**

สิ่งที่**ห้ามตัดออก**ไม่ว่าจะ optimize อะไร: บก.อ่านเต็มทุกตอน · ตรวจ continuity เต็มทุกตอน (Claude เท่านั้น) · calibration เต็มรูปแบบ · Gate ตรวจโครงก่อนเขียน
สิ่งที่ optimize ได้: batch วางแผน+Gate ครั้งละหลายตอน (อันนี้ยิ่ง**ช่วย**ความไหลลื่น — วินเห็นจังหวะปมทั้งช่วงพร้อมกัน) · สคริปต์เช็คกลอัตโนมัติ (เสริม ไม่แทนคน) · DeepSeek เขียนภายใต้กำกับ (ถ้า A/B ผ่านบก.)

กลไกเฝ้าความต่อเนื่อง (เพิ่มใหม่):
1. **สมุดปมค้าง `threads.md`** — วินเป็นเจ้าของ: ทุกปมที่ผูก (setup) ลงทะเบียน: ปมอะไร / ผูกไว้ตอนไหน / ใครรู้บ้าง / กำหนดจ่าย (payoff) ตอนไหน / สถานะ (เปิด/จ่ายแล้ว/เลื่อน) — อัปเดตทุกครั้งที่ตอนผ่านบก. · คนตรวจ continuity ต้องเทียบ threads.md ทุกรอบ: ปมที่ถึงกำหนดจ่ายแล้วไม่จ่าย = ทักทันที, ปมใหม่ที่ไม่ลงทะเบียน = ทักทันที
2. **กฎรอยต่อระหว่างตอน** — ฉากแรกของตอน N+1 ต้อง "รับ" hook ของตอน N (ตอบ/ต่อยอด/อยู่ในเงาของมัน) — ถ้าตั้งใจเว้น (เปลี่ยน POV/ข้ามเวลา) ต้องระบุในแผนฉากว่า defer hook ไปจ่ายที่ไหน ห้ามเงียบหาย
3. **เช็คเสียงตัวละครต่อตอน** — ผู้กำกับ/คนตรวจเทียบบทพูดทุกตัวกับ `speechTone`+`voiceExamples` ใน characters.md — ตัวละครพูดผิดเสียง = ระดับร้ายแรง เทียบเท่าตัวเลขผิด
4. เป้าเวลาใหม่: ~15–25 นาที/ตอน (จาก ~45–50) — ได้จาก batch แผน + DeepSeek + ตรวจขนาน โดยไม่แตะด่านคุณภาพข้างบน

## v2.4 — ความละเอียดของ canon + สถานะปัจจุบันในบรีฟ (CEO)

> **ใช้ schema เดียวกับแอปแชท/นิยาย** (`novel-next/src/lib/chat-types.ts`) เพื่อให้ canon ทีมนิยายกับข้อมูลในแอปเป็นชุดเดียวกัน — ตัวละคร/lore จากนิยายโยนเข้าแชท RP ได้ทันทีโดยไม่ต้องแปลง

1. **ทะเบียนไอเทม + สถานที่** — วินต้องทำ `items-locations.md`: ไอเทมสำคัญทุกชิ้น (ลักษณะ, ที่มา, ใครถือ, สถานะปัจจุบัน, กฎการใช้) และสถานที่ทุกแห่งที่มีฉาก (layout, บรรยากาศ, ใครประจำอยู่, กฎเข้าออก) — **เขียนแต่ละรายการเป็นรูปแบบ `LoreEntry`**: `keys` (คำที่ trigger), `text` (ข้อเท็จจริง 1-3 ประโยค), `always`/`priority` — ละเอียดพอให้นักเขียน/DeepSeek เขียนได้โดยไม่ต้องเดา และพร้อมโยนเข้า lorebook ของแชท
2. **ตัวละครต้องมีเสียงพูด** — characters.md ทุกตัว ใช้ฟิลด์ตาม `ChatChar`: `appearance`, `outfit`, `description` (ปูม), `mindset` (วิธีคิด/ค่านิยม), `behavior` (นิสัย/พฤติกรรม), `pronounSelf`/`pronounOther`, `speechTone` (คำติดปาก ระดับภาษา จังหวะ), **`voiceExamples` — ตัวอย่างประโยคพูดจริง 2-3 ประโยคต่อตัว** ให้นักเขียน/DeepSeek เลียนเสียงได้ทันที
3. **แผนฉากรายตอนต้องมี block "สถานะปัจจุบัน"** — รูปแบบ `ChatStateCard` ต่อตัวละครหลักในตอน: `location`, `outfit`, `inventory` (ของสำคัญที่ถือ), `whoKnowsTruth` (ใครรู้ความลับอะไรแล้ว ณ ตอนนี้), `goals` + ความสัมพันธ์แต่ละคู่อยู่ขั้นไหน (อ้างบันไดใน characters) + ปมค้างจากตอนก่อน — เพราะ DeepSeek ไม่รู้ว่าความสัมพันธ์/สถานการณ์เปลี่ยนไปแล้ว ถ้าบรีฟไม่บอก
4. **ห้ามมโนไอเทม/สถานที่** — นักเขียน (หรือ DeepSeek ในดราฟต์) ต้องการไอเทม/สถานที่ใหม่ที่ไม่อยู่ในทะเบียน → **ถามวินก่อนผ่าน canon-qa ตกลงกันแล้วค่อยใช้** (ขยายกฎห้ามมั่ว v2.1 ให้ครอบคลุมของและฉาก) — ผู้กำกับเจอ DeepSeek มโนของใหม่ในดราฟต์ = แก้เป็นของในทะเบียน หรือส่งคำถามถึงวิน ห้ามปล่อยผ่าน

## v2.3 — Gate ตรวจโครงก่อนเขียน (CEO)

หลังวินส่งโครง (canon + outline + แผนฉากรายตอน) **ห้ามเริ่มเขียนจนกว่าจะผ่าน 2 ด่าน**:
- **ด่านบก. (ไปรอดไหม)** — อนันต์ตรวจมุมตลาด/คนอ่าน: hook แรงพอไหม จังหวะตอนดีไหม เดิมพันยกระดับไหม ตรงบรีฟไหม → ไม่รอด = ตีกลับวินพร้อมเหตุผลรายข้อ
- **ด่าน continuity (สัมพันธ์กันไหม)** — ตรวจโครงเทียบ canon: ตัวเลข/timeline/กฎโลกขัดกันเองไหม ความลับเฉลยถูกลำดับไหม → ขัด = ตีกลับวิน
- ผ่านทั้งสองด่าน = **โครง confirmed** → ค่อยเขียน → ตรวจคำ/ตรวจภายในตอน (ทันทีต่อตอน ตามข้อ 5 ของ v2.2) → calibration + ตรวจข้ามตอน → บก.ปิดงาน
- เหตุผล (ข้อมูล R0): บั๊กร้ายแรงทั้ง 2 จุดของรอบแรกอยู่ในระดับโครงอยู่แล้ว แต่ถูกจับหลังเขียน prose เสร็จ — แก้แพงกว่าหลายสิบเท่า ตรวจโครงเพิ่ม ~1 ขั้น แต่ตัดความเสี่ยง "เขียนผิดทางทั้งชุด" ทิ้ง

## v2.2 — กฎลดเวลา/ต้นทุน (จากรายงานวิเคราะห์รอบ «ทะลุมิติพันปี» R0: 1.50M tokens / ~2.5 ชม.)

2. **ถาม-ตอบ canon: ตอบใน canon-qa.md อย่างเดียว** ห้าม rewrite ไฟล์ canon ระหว่างรอบ — merge เข้า canon ทีเดียวเมื่อปิดรอบ (R0 เผา ~115k เพราะแก้ไฟล์ใหญ่ทุกรอบ)
3. **Calibration แนบ excerpt** — คนตรวจต้องใส่ข้อความรอบจุดที่ถาม (±2 บรรทัด) ในรายการคำถาม เพื่อให้นักเขียนตอบได้โดยไม่ต้องอ่านต้นฉบับใหม่ทั้งเรื่อง
4. **แบ่งงานตามโมเดล (Claude กำกับ, DeepSeek ลงแรง)** — สะพาน: `bun tools/ds-gen.ts --prompt <f> --out <f>` (ใช้ deepseek-v4-flash, ปิด thinking อัตโนมัติ)
   - งาน **judgment** อยู่กับ Claude: วิน (canon), อนันต์ (ตัดสิน/วัด), ตรวจ continuity, calibration, การเขียนบรีฟ
   - งาน **ปริมาณ** โยน DeepSeek: เจน prose ตามบรีฟละเอียดต่อตอน (โครงฉาก+เสียงเล่า+ศัพท์ canon+ตัวอย่างย่อหน้า), ดราฟต์พิสูจน์อักษรรอบแรก
   - Claude ผู้กำกับต้องตรวจรับผลงาน DeepSeek เทียบบรีฟทุกชิ้น (ผ่าน/ตีกลับพร้อมเหตุผล ตีกลับได้สูงสุด 2 รอบ แล้วเขียนเองถ้ายังไม่ผ่าน)
   - สถานะ: ep004 คือ A/B ทดลองแรก — ถ้าคุณภาพผ่านบก. ใช้เป็นมาตรฐานตั้งแต่ ep005
5. **Pipeline ต่อตอน (CEO, v2.2)** — งานเขียนหลายตอน ห้ามเขียนรวดเดียวจบทั้งชุดแล้วค่อยตรวจ: ตอนไหนเสร็จเข้าด่านตรวจทันที (พิสูจน์อักษร + continuity ภายในตอน/เทียบ canon) ขนานกับการเขียนตอนถัดไป แล้วปิดท้ายด้วย **ตรวจข้ามตอน 1 รอบ** เมื่อครบชุด (บั๊กข้ามตอนต้องเห็นทุกตอนถึงจับได้) — ไม่ตรวจกลางตอนที่เขียนไม่จบ เพราะ continuity มักเฉลยท้ายตอน = false alarm + เปลือง token อ่านซ้ำ

> ใช้เมื่อ: CEO ส่งพล็อตเข้ามา (ไอเดียหยาบๆ ก็ได้) หรือสั่งรอบแก้งานเดิม

> (1) คนตรวจเจอ "เชิด/เชิญ" แล้วฟันธงเองว่าคำผิด ทั้งที่อาจเป็นมุกตั้งใจ
> (2) คนตรวจรายงานความยาวตอนผิด (นับพยางค์ปนคำ) แล้วความผิดลามขึ้นไปถึงเกรดของบก.

## ขั้นตอน

1. **รับพล็อต** — CEO ส่งพล็อต (ความยาวเท่าไหร่ก็ได้) → มะลิวิเคราะห์ว่าเข้า trope ไหนบนชาร์ต เสนอจุดปรับ (ไม่บังคับ) → อนันต์เขียนบรีฟ: โทน, กลุ่มเป้าหมาย, ความยาว/จังหวะตอน, ขอบเขตเนื้อหา, นิยาม "ผ่าน"
2. **สถาปัตยกรรมเรื่อง** — วิน: world bible (เผ่า/ตัวละคร/เทคโนโลยี/สเกลพลัง/ปริศนาแกนเรื่อง) + โครงซากา + outline arc แรก + แผนฉากรายตอน + template สำหรับเจนเผ่า/ตัวละครใหม่ภายหลังโดยไม่ขัด canon
2.5 **Gate ตรวจโครง (v2.3)** — บก.ตรวจ "ไปรอดไหม" + continuity ตรวจ "สัมพันธ์กับ canon ไหม" → ตีกลับวินจนผ่านทั้งสองด่าน ค่อยปล่อยเขียน
3. **เขียน** — แพรวา: เขียนตอนจากโครงที่ confirmed แล้ว (ไม่ต้องคิดโลกเอง)
   - **กฎห้ามมั่ว (CEO, v2.1)**: จุดไหนไม่มั่นใจหรือ canon ไม่ครอบคลุม **ห้ามแต่งเอง** — ต้องส่งคำถามถึงวินก่อนเขียน วินตอบ+อัปเดต canon แล้วถาม-ตอบวนจนนักเขียนไม่มีคำถามค้าง (บันทึกลง `story/<เรื่อง>/canon-qa.md`) ค่อยเริ่มเขียน
4. **ตรวจ (ห้ามแก้)** — continuity (เทียบ canon ของวินด้วย) + พิสูจน์อักษร รันขนาน ผลออกเป็น **รายการคำถาม** ไม่ใช่คำสั่งแก้ แต่ละรายการ: ตำแหน่ง / สิ่งที่เห็น / สงสัยว่า "ผิดจริง" หรือ "ตั้งใจ (มุก/สำนวน/เสียงตัวละคร)"
5. **รอบเทียบความเข้าใจ (calibration)** — แพรวาตอบทีละรายการ: `แก้เลย` (พลาดจริง) / `คงไว้` + เหตุผล (ตั้งใจ) / `ไม่แน่ใจ` → ได้ **รายการตกลงร่วม** แยก 3 กอง: แก้ / คง / ส่งบก.ตัดสิน — **ยังไม่แตะต้นฉบับจนกว่ารายการนี้จะปิด**
6. **บก.ตรวจรับ** — อนันต์อ่านต้นฉบับ + รายการตกลงร่วม แล้วต้องตอบให้ครบ 3 อย่างต่อจุด ห้ามพูดลอยๆ:
   - **ขยาย**: ตรงไหน + ขยายไปทางไหน (อารมณ์? รายละเอียดฉาก? ปูเส้นเรื่อง?) + ประมาณกี่คำ
   - **ตัด**: ตรงไหน + เพราะอะไร (ยืด/ซ้ำ/หลุดโทน/เสี่ยงเรต)
   - **คำเคาะข้อพิพาท**: ทุกข้อที่ค้างจากกอง "ส่งบก.ตัดสิน"
   - ปิดท้าย: เกรด + verdict (ผ่าน / แก้ก่อนลง / ตีกลับ) + เงื่อนไขผ่านรอบหน้า
7. **รอบแก้** — แพรวาแก้ตามรายการตกลงร่วม + คำสั่งบก. → เข้ารีวิวรอบเช็กเร็ว (ตรวจเฉพาะจุดที่แก้)
