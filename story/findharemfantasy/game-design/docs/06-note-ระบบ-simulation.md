# NOTE: ระบบ Dating Simulation (ตารางเวลา/สถานที่) — สำหรับอนาคต

> ⚠️ **ยังไม่ทำใน Phase 1** — ไฟล์นี้แค่ "จดไอเดียกันลืม"
> Phase 1 โฟกัสแค่: เข้าเกม → คุย → เซฟ → จบเกม ให้ออกมาเป็นเกมก่อน
> ระบบนี้ค่อยลงมือจริงหลัง MVP เล่นจบได้แล้ว (น่าจะ Phase 2 เป็นต้นไป)

## ภาพที่อยากได้ (เป้าหมายระยะยาว)
เกมจีบสาวแบบ **simulation** จริง ๆ ที่:
- ตัวละครสาวแต่ละคนมี **ตารางเวลา (schedule)** ของตัวเอง
- เวลาในเกมเดินเป็น **ช่วง (slot)** เช่น เช้า / สาย / บ่าย / เย็น / กลางคืน
- แต่ละช่วง สาว ๆ จะ **อยู่คนละสถานที่** ตามกิจวัตร
- ผู้เล่นเลือกว่าจะ "ไปที่ไหน / ตอนไหน" เพื่อไปเจอคนที่อยากเจอ → คือแกน gameplay

## องค์ประกอบที่ต้องออกแบบ (ตอนถึงเวลา)
1. **ระบบเวลา (Time/Calendar)**
   - วัน + ช่วงเวลาในวัน (เช่น 5 slot/วัน)
   - การกระทำหนึ่งอย่าง (คุย/เดินทาง) กิน 1 slot
2. **สถานที่ (Locations)**
   - เช่น แคมป์, ตลาดเมือง, ป่า, ลำธาร, หอสมุดเอลฟ์ ฯลฯ
   - ผู้เล่นเลือกเดินทางระหว่างสถานที่
3. **ตารางของตัวละคร (Character Schedule)**
   - ตารางว่า "ใคร อยู่ที่ไหน ช่วงไหน"
   - ตัวอย่างโครงข้อมูล (ไว้ทำทีหลัง):
     ```
     liena:
       เช้า   -> ลำธาร
       สาย   -> แคมป์
       บ่าย  -> ป่า
       เย็น   -> แคมป์ (กองไฟ)
       กลางคืน-> เต็นท์
     ```
   - ตารางอาจ "เปลี่ยน" ตามระดับพันธะ/เหตุการณ์ (เช่น พันธะสูงขึ้น เธอชวนไปที่พิเศษ)
4. **อีเวนต์ตามเงื่อนไข (Events)**
   - เจอใคร ที่ไหน ตอน Bond ถึงระดับหนึ่ง → ปลดล็อกฉากพิเศษ
   - เชื่อมกับ "ระบบคำสั่งเป็นขั้น" (ดู [phase-1-design/05-ระบบเกม-phase1.md](phase-1-design/05-ระบบเกม-phase1.md))
5. **ทรัพยากร/พลังงานของผู้เล่น (ออปชัน)**
   - จำกัดจำนวนกิจกรรมต่อวัน เพื่อให้ต้อง "เลือก" ว่าจะโฟกัสจีบใคร

## ทำไมเลื่อนไว้ก่อน (เหตุผล)
- ระบบนี้ทำให้ scope บานปลายเร็วมาก (ต้องมีหลายสถานที่ หลายตาราง หลายอีเวนต์)
- มือใหม่ควร **พิสูจน์ว่าทำเกมจบได้ก่อน** ด้วย visual novel เส้นตรงใน Phase 1
- โครงสร้างที่เราวางไว้ (แยก `GameState` ออกจากการแสดงผล) **รองรับการต่อยอดระบบนี้อยู่แล้ว** — เพิ่มทีหลังได้โดยไม่ต้องรื้อ

## สิ่งที่ "เผื่อไว้ตั้งแต่ตอนนี้" (เพื่อไม่ต้องรื้อใหญ่)
- เก็บ Bond แยกต่อตัวละครใน `GameState.bond` (ทำแล้ว) → รองรับหลายสาว
- ออกแบบบทเป็น "ก้อน scene/event" ย่อย ๆ → ภายหลังเอามาแขวนกับ slot เวลา/สถานที่ได้
- อย่า hard-code ว่า "หลังคุยจบ ไปฉากไหนต่อ" แบบตายตัวเกินไป → เผื่อให้ระบบเวลามาคุมลำดับทีหลัง
