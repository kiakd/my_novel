# รองรับหลายแพลตฟอร์ม (Cross-Platform Design)

> เป้าหมาย: ออกแบบให้โค้ดชุดเดียวรันได้หลายแพลตฟอร์ม ตั้งแต่ Phase 1 โดยไม่ต้องรื้อทีหลัง
> หลักคิด: **แยก "ตรรกะเกม" ออกจาก "การแสดงผล/อินพุต/แพลตฟอร์ม"** — ตรรกะอยู่ใน `GameState` (platform-agnostic) ส่วนที่ต่างกันต่อแพลตฟอร์มให้ห่อเป็นชั้นบาง ๆ
> ⚠️ ก่อนลงมือแต่ละส่วน **อ่าน docs จริงเสมอ** (ดู [godot-reference/INDEX.md](godot-reference/INDEX.md)) อย่าเดา API

## เป้าหมายแพลตฟอร์ม
| กลุ่ม | แพลตฟอร์ม | ความสำคัญ |
|------|-----------|-----------|
| Desktop | Windows / macOS / Linux | หลัก (พัฒนา/เทสต์) |
| Mobile | Android / iOS | รอง (เฟสหลัง) |
| VR | Meta Quest (standalone, Android) / PCVR (OpenXR) | เป้าหมายปลายทาง |
| Web | HTML5 | ออปชัน (เดโม) |

## ตารางสรุปประเด็นที่ต้องคุมต่อแพลตฟอร์ม
| ประเด็น | กฎที่ต้องทำตั้งแต่ตอนนี้ |
|---------|--------------------------|
| เซฟไฟล์ | ใช้ `user://` เท่านั้น (ห้าม hardcode path OS) — เราทำแล้วใน save_system |
| ชื่อไฟล์ | `ตัวพิมพ์เล็ก_มีขีดล่าง` (Linux/Android case-sensitive) — เราทำแล้ว |
| อินพุต | ผ่าน **InputMap action** เท่านั้น (รองรับ คีย์บอร์ด/เมาส์/ทัช/จอย/VR) |
| หน้าจอ | ออกแบบด้วย **anchor + container** ไม่ fix พิกัด — รองรับหลายอัตราส่วน |
| ฟอนต์ไทย | **ต้องฝังฟอนต์ที่มีอักษรไทย** (ดีฟอลต์ Godot ไม่มี → ตัวหนังสือไทยจะเป็นกล่อง □) |
| เรนเดอร์ | เลือก backend ตามเป้า (ดูหัวข้อด้านล่าง) |
| วงจรชีวิตแอป | มือถือ/VR: autosave ตอนแอปถูกพัก (lose focus) |

## 1) อินพุต — ใช้ InputMap (สำคัญสุดสำหรับ cross-platform)
อย่าผูกปุ่มตรง ๆ ในโค้ด ให้สร้าง **action** ใน Project Settings > Input Map แล้วอ้าง action แทน
- action ที่เกมต้องมี (Phase 1): `advance` (ไปต่อ), `ui_accept` (มีอยู่แล้ว), ภายหลัง `skip`, `menu`
- map หลายอินพุตเข้า action เดียว:
  - `advance` ← คลิกซ้าย / Space / Enter / **แตะจอ (touch)** / ปุ่ม A ของจอย / trigger ของ VR controller
- โค้ดเช็ก `event.is_action_pressed("advance")` → ทำงานเหมือนกันทุกแพลตฟอร์ม
- **TODO โค้ด:** ปรับ `dialogue_scene.gd` ให้ใช้ action `advance` แทนการเช็ก mouse button ตรง ๆ (ตอนนี้ยังเช็ก mouse+ui_accept) และเพิ่ม touch
- 📖 อ่าน: Godot Manual → "Input examples" / "InputEvent" ก่อนทำ

## 2) หน้าจอ & การปรับขนาด (Resolution / Aspect)
- base resolution 1280×720 (ตั้งใน project.godot แล้ว) + `stretch/mode = canvas_items`, `aspect = keep` (ตั้งแล้ว)
- UI ทุกตัวใช้ **anchor + Container** (เราทำแล้ว) → ยืดตามจอได้
- มือถือ/VR มีอัตราส่วนหลากหลาย + รอยบาก (notch) → ใช้ **safe area** (`DisplayServer.get_display_safe_area()`) จัดวางปุ่มสำคัญ
- ทดสอบหลายอัตราส่วน: 16:9, 16:10, 4:3, จอมือถือแนวนอน
- 📖 อ่าน: Manual → "Multiple resolutions"

## 3) ฟอนต์ไทย (ต้องทำก่อน export จริง — ไม่งั้นไทยไม่ขึ้น)
- ฟอนต์ดีฟอลต์ของ Godot **ไม่มีกลีฟภาษาไทย** → ข้อความไทยจะกลายเป็นกล่องว่างเมื่อ export (โดยเฉพาะมือถือ/เว็บ)
- วิธีแก้: ฝังฟอนต์ไทย (เช่น **Noto Sans Thai**, Sarabun) เป็น **Theme default font** ของโปรเจกต์
  1. วางไฟล์ฟอนต์ใน `assets/ui/fonts/`
  2. สร้าง Theme (`assets/ui/theme.tres`) ตั้ง default font + กำหนดใน Project Settings > GUI > Theme > Custom
- 📖 อ่าน: Manual → "Using Fonts" / "Internationalizing games"
- ⚠️ **เป็น action item ลำดับต้น** เพราะเกมเราเป็นภาษาไทยทั้งหมด

## 4) เรนเดอร์ (Rendering backend)
Godot 4 มี 3 backend — เลือกตามเป้าแพลตฟอร์ม:
| Backend | เหมาะกับ | หมายเหตุ |
|---------|----------|----------|
| **Forward+** | เดสก์ท็อปสเปกสูง (ปัจจุบันเราใช้ตัวนี้) | สวยสุด แต่ไม่เหมาะมือถือ/Quest |
| **Mobile** | Android/iOS/**Meta Quest** | เป้าหมาย VR ปลายทาง |
| **Compatibility** | เครื่องเก่า/**เว็บ**/มือถือสเปกต่ำ | กว้างสุด (OpenGL) |
- **แผน:** พัฒนา Phase 1 บน Forward+ ไปก่อน → เมื่อเริ่มทำ Quest/มือถือให้สลับเป็น **Mobile**; ถ้าทำเดโมเว็บใช้ **Compatibility**
- เป็น 2D VN เปลี่ยน backend ภายหลังกระทบน้อย แต่ของ 3D/VR (เฟสหลัง) ต้องเลือกให้ตรง
- 📖 อ่าน: Manual → "Renderers"

## 5) วงจรชีวิตแอป (Mobile / VR lifecycle)
- มือถือ/VR แอปถูกพักได้ตลอด (สลับแอป/ถอดแว่น) → ต้อง **autosave**
- จับ notification ใน autoload เช่น:
  ```gdscript
  func _notification(what):
      if what == NOTIFICATION_APPLICATION_PAUSED or what == NOTIFICATION_WM_GO_BACK_REQUEST:
          SaveSystem.save_game()
  ```
- เว็บ (HTML5): `user://` เก็บใน IndexedDB ของเบราว์เซอร์ — ต้อง `OS.is_userfs_persistent()` / flush; การเซฟอาจหายถ้าเคลียร์ browser data
- 📖 อ่าน: Manual → "Handling quit requests" / class `Node` (notifications)

## 6) VR (OpenXR) — เผื่อโครงไว้
- ตรรกะเกม (GameState) ไม่ผูกกับ VR อยู่แล้ว → ฉาก VR แค่เปลี่ยน "การแสดงผล/อินพุต"
- Quest = Android + Mobile renderer + OpenXR; PCVR = OpenXR ผ่าน SteamVR
- VR ต้องการ 72–90 fps คงที่ → งบ performance เข้มกว่าจอปกติ (ดู [05-สเปก-3d-art.md](05-สเปก-3d-art.md))
- 📖 อ่าน: Manual → "XR" / "Setting up XR" ก่อนเริ่มเฟส VR

## 7) Export Presets (ทำตอนจะปล่อยแต่ละแพลตฟอร์ม)
| แพลตฟอร์ม | ต้องเตรียม |
|-----------|-----------|
| Windows/Linux | export template (ลงในตัว) |
| macOS | ต้อง sign/notarize (ต้องมีเครื่อง Mac) |
| Android/Quest | Android SDK + JDK + keystore |
| iOS | ต้องมี Mac + Xcode + Apple Developer |
| Web | export template + เสิร์ฟผ่าน https (cross-origin headers) |
- เก็บ `export_presets.cfg` ไว้นอก git (มี secret) — อยู่ใน .gitignore แล้ว
- 📖 อ่าน: Manual → "Exporting" (มีหน้าแยกต่อแพลตฟอร์ม)
